# Server black-box acceptance report (#140)

## Result and decision

The local main baseline does not meet server E2E acceptance. The real Target
Service receives Observation messages but no matching `targets.updated` message
arrives within the eight-second acceptance budget. Five scenarios fail at this
same prerequisite; these are not five independently demonstrated product defects.

The independent real DBMS protocol control passes. Target Service SQL integration
is blocked by undocumented launch arguments and domain schema. Existing smoke
regressions and the documented CLI pass. No production code was changed.

The tests can be pushed to a development branch as explicitly unfinished
acceptance work. Keep the `server_e2e` tag and do not make the currently failing
command a required default CI check. An ordinary green CI run would not prove
server acceptance. Do not close #140 or claim release readiness from this run.
No push or PR was performed during this work.

## Findings

### F-01: no observable server Target publication

- Requirement: `spec/data-model.md`, `spec/broker-protocol.md`,
  `spec/target-aggregation.md`, FR-15 through FR-17 in `docs/requirements.md`.
- Input: target `17`, observer `A`, latitude `59.95`, longitude `30.311`,
  confidence `0.8`, current Unix millisecond timestamp.
- Expected: a five-field Target on `targets.updated`, same location and
  last-seen timestamp, with probability matching the decay formula.
- Actual: Broker readiness is established, Target Service logs receipt, but
  the test subscriber receives no Target. The service stays alive.
- Impact: blocks verification of two-observer probability, deduplication,
  invalid-input handling, periodic decay and the server-to-Map redraw.
- Classification: missing acceptance functionality on this baseline; not
  evidence that this test branch introduced a regression. Related work: #130/#137.

Representative diagnostics from the raw acceptance log:

```text
ACCEPTANCE: no server-produced targets.updated for 17 within 8s; sent only Observation, no Target injection
observation stored targetId="17" observerId="A" timestamp=1794505049217 (targets in memory=1)
cleanup checked: processes waited for, PIDs absent, sockets absent, private directory removed
```

The timestamp above is from the Map scenario. Bootstrap retries keep exactly
the same observer/timestamp to cover subscription races, without manufacturing
independent evidence. The result does not demonstrate whether aggregation is
correct or incorrect internally: its observable output is missing.

### C-01: SQL integration launch/schema contract is incomplete

`spec/dbms-protocol.md` specifies transport, framing and typed replies, but does
not fix the Target Service CLI option for an isolated DBMS socket or the service's
domain table schema. The `targets` table in `spec/sql.md` is an example. Treating
it as normative, or inventing a `-dbms` flag, would turn an assumption into a
false compatibility failure.

The test accepts explicit JSON launch arguments with a `{dbms}` placeholder and
a read-only SELECT projecting the five Target values. Once the service owner
documents these interfaces, configure them and run the same tests. The SQL
integration probe never inserts test Target rows; a matching domain row must
be written by the real service. Independent DBMSProtocol success does not prove
that Target Service uses DBMS.

## Reproduction

Use an installed Go toolchain compatible with the host, then run from
`tests/system-smoke`. On macOS, short `TMPDIR` paths avoid Unix socket limits:

```sh
export GOPROXY=off GOSUMDB=off GOTOOLCHAIN=local GOWORK=off TMPDIR=/tmp
go vet -tags server_e2e ./...
go test -race -count=1 -timeout 5m ./...
go run -mod=readonly .
go test -tags server_e2e -race -run '^TestServerE2E$' -count=1 -timeout 5m -json .
go test -tags server_e2e -race -run '^TestServerE2E/SQLIntegration$' -count=1 -timeout 3m -json .
```

No SQL integration configuration was supplied in the recorded runs. Configuration
instructions are in `tests/system-smoke/README.md`. Downloading a Go toolchain
was a setup step; component builds and test execution used no module downloads.
